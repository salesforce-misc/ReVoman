= Performance

ReṼoman treats both deployment shapes as release-critical performance targets:

* *Cold standalone*: one execution in a fresh process, including startup and peak-resource costs.
* *Warm embedded*: repeated execution in a long-lived JVM, including steady-state latency and
  allocation costs across independent forks.

Performance depends on the workload, target classpath, JDK, host, and metric provider. Release
comparisons therefore rerun a fixed baseline and the candidate in randomized paired blocks on a
controlled host. Cold and warm baseline-versus-baseline checks must both pass before candidate
results are eligible for a claim. Ordinary CI validates harness structure and deterministic math;
it does not enforce timing or memory thresholds.

This page intentionally makes no numeric performance claim. A release claim may cite only verified
`revoman-benchmark/v1` or `revoman-benchmark-jmh/v1` artifacts captured under the
link:{gh-blob}/docs/superpowers/benchmarks/baseline.md[v1 reproducible evidence protocol]. Legacy
human JMH output is not comparable evidence.

Controlled Linux samples record observed external-power sysfs evidence separately from an
administrator-owned fixed-mains attestation. Fixed mains is valid only when the host's
`/sys/class/power_supply` directory exists and is empty, meaning runtime power telemetry is not
applicable; it is not an inferred healthy power state. Smoke samples record unavailable power
evidence and cannot support release claims.
